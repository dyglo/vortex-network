## What changed

- Applied a shared 30-second Pesapal API timeout with a 10-second connection timeout.
- Added retries for transient `ReadTimeout` and `ConnectTimeout` failures, with 1- and 2-second backoff.
- Applied the wrapper to token retrieval, IPN registration, order submission, and transaction-status requests.

## Why

Pesapal sandbox connectivity has intermittent latency and packet loss from this network. Retrying transient timeouts makes these API calls resilient without changing payment business logic.

- Compiled `app/services/pesapal.py`.
- Exercised the retry helper with two simulated read timeouts followed by a successful response.
